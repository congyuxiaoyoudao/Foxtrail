一、保留已经选择的规则
驻足时生态继续；只在生命增长时耗水；生命下降时显示阶段回退；首次成熟立即向左右各播一颗，之后每30秒尝试；植物与待萌芽种子合计最多5个；温度跨阈值改变当前地貌。萌芽成功率仍按当前代码100%处理，不替用户决定此前未勾选的概率方案。
一关72格，只有关内相邻交换与降雨，不能与其他关相连。初始站点主题限制雪地、沙地不能直接相邻；演化后类别变化不再强制维持初始站点主题。

湿度 M = 当前土壤水量 / (泥土量+10)。下表湿度为百分数；泥土量是1～100数值，非水量。
每项“a/b/c”为第一、第二、第三阶段环境门槛，均包含下界。最高可生长阶段取湿度与泥土满足阶段的较低者。

共同数值：生命上限90；1～30第一阶段，31～60第二阶段，61～90第三阶段；生长+1生命/秒，衰退-1生命/秒。土壤与湿度最大允许值均100，避免土壤更肥或湿度超过90%反而判死。
未满足第一阶段门槛、地貌不适合、致死淹水：持续衰退；满足生存门槛但超过当前阶段生命上限：衰退到新上限。稳定达到上限后不耗水，不恢复生命也不耗水。
种子萌芽单次耗水仍为0.1；30秒待萌芽期限、每秒检查沿用代码。不是每秒扣0.1。满容量不能播入，植物死亡释放容量。成熟冷却按植物实例保存，阶段反复跨越不能无限重置“首次播种”。
地表水10以下不算中等积水；10<S<25为中等，S>=25为深水。只有本表胡杨耐中等水深；深水仍伤害全部这8种陆生植物。深水不再额外生成水草；水深仍用于池塘与陆生植物判定。

玩法差异：草丛与灌木容易形成初步覆盖；松树需要更好的土壤和补水；云杉可以经历雪地融化继续存活；雪莲花保留雪地专属性；梭梭、仙人掌适合低水条件；胡杨是沙地补水改造后能够延续的树木。
这意味着强行把雪地或沙地变成平原，会导致雪莲花、梭梭、仙人掌逐渐衰退，并非“所有植物越浇越好”。初始生成池和生存地貌必须分开：云杉能活在平原，不代表开局平原随机生成云杉。

三、初始化与水循环
普通地块：
雪地：泥土30～65，湿度45%～75%，温度1～4。
平原：泥土40～80，湿度45%～70%，温度7～10。
沙地：泥土20～50，湿度20%～40%，温度14～18。
初始高度0/1，普通地表水0～3。每格30%概率生成1株、70%概率0株；品种从对应初始植物池等概率选取。自然植物生命随机2～环境生命上限。
每站另生成1个低洼水源格：本站第3/7/11格随机选一格，高度0，两邻格高度1，土壤满水，地表水26～32，初始无陆生植物。此项是本次模拟输入，不能误认为原项目已经如此生成。

容量 C = D+10。
渗透量 = min(S, C-W, 0.03×D)，每秒一次，土壤增加多少地表扣多少。
潜在蒸发 E = 基础蒸发量 × max(0.15, 1-0.004×D-0.3×植物数/5)。基础蒸发量随机0.01～0.03。
新增干土衰减：若本秒蒸发前 S<=0，E再乘 clamp(M/0.4, 0.05, 1)；有地表水时不乘。实际扣除量仍不能大于现存水量。按现有代码优先扣地表、不足再扣土壤，只有实际扣掉的量计入水汽。
含义：湿地仍能产生水汽，干土失水逐渐减慢；不会把小数量级的沙地土壤水很快蒸光。
相邻土壤水：比较湿度确定方向，单边每秒上限0.02单位，沿用同步交换与容量限制。
水面高度 = 地面高度 + S/35；土壤满水才允许地表外流，单边每秒上限1单位，沿用供给约束。水深外观分档不能用来代替连续水面高度。
温度相邻交换：单边每秒上限从0.01调整为0.002，沿用原来的差值/3限制及同步结算。
雨：每40秒抽取当前关连续15格，水汽门槛30，雨量min(0.9×水汽和,80)，持续40秒。按各格水汽占比扣除，均匀落雨。玩家收集上限与库存规则保留。本次生态模拟没有模拟玩家雨水采集，不能用它证明资源获取体验已经平衡。

四、新水温公式：水量决定幅度，温度渐变，干燥后慢慢回温
旧条件“地表水达到20才向10靠拢”不适用：玩家最多携带20，渗透、外流或蒸发任一发生后，地表水就可能不足20。即使把0.05改成0.3，也经常没有触发机会。

每格初始化时记录，之后不可每秒重设：
T0 = 初始温度（气候基准）。
B = 初始土壤水 + 初始地表水（蓄水基准）。
两项是独立于当前状态的持久数据，未来必须进入存档。

每秒在相邻交换、渗透、地表流动、蒸发后，植物生长前：
A = max(0, 当前土壤水 + 当前地表水 - B - 1)
I = clamp(A / 8, 0, 1)
目标温度 Tgoal = T0 + (10-T0)×I

若 abs(Tgoal-10) < abs(T-10)：
    ΔT = clamp((Tgoal-T)×0.06, -0.15, 0.15)
否则：
    ΔT = clamp((Tgoal-T)×0.002, -0.01, 0.01)
T = clamp(T+ΔT, 0, 20)

类别：T<5雪地；5<=T<12平原；T>=12沙地。
1单位为扰动容忍量；额外保留9单位水时影响系数达到1。不是投9单位就保证达到1：流走、植物消耗、蒸发和采集都会减少真正保留的水。
使用土壤水+地表水，避免渗透本身立刻取消效果。基准B避免原本湿润的雪地开局自动化为平原。温度结算不消耗水，生长/蒸发另算，不能重复扣水。
慢回温是本候选版新增的设计建议：水量降低后不瞬间复原，也不让每一点小雨无限累计、最终把所有地貌推成平原。水只能将环境推向10，不能仅靠加水把平原变成雪地或沙地；干燥后会逐渐接近该格原始气候。
所有系数按1秒固定模拟步计算。不能在Unity每帧直接调用一次；离线结算也要保持相同时间尺度。

五、已完成的隔离测试
最终候选 Thermal.json：540组，涵盖初温0、2、4、12.1、16、20；泥土20、50、80；湿度20%、60%、100%；投水0、2、5、10、20；单格与3格邻接；每组300模拟秒。
Plants.json：8种植物×5档投水=40组，每组180秒。
Scenarios.json：4种气温×空地/3株正在生长的植物×4档投水=32组，每组600秒，包含繁殖及邻接。
Geometry.json：18组，比较饱和土壤下的低洼、平地、高地。
Ecology.json：20个随机种子，各72格，运行3600模拟秒；无玩家干预，保留生长、传播、水流、气候、降雨。
Invariants.json：5项全部通过——无额外水无温度变化；无损耗单格温度结算不消耗水且不越过10；成熟植物不耗水；衰退阶段回退；无蒸发/生长的相邻交换场景水量守恒。

典型3格场景，中央投水，两邻格同初始环境：
普通雪地T=2、泥土50、湿度60%，空地：10水21秒变平原；600秒观察窗内累计维持平原308秒。20水21秒变平原，累计580秒。
普通沙地T=16、泥土30、湿度25%，空地：10水29秒变平原，累计112秒；20水28秒变平原，累计365秒。
极冷T=0：10水35秒变平原，累计201秒；20水35秒，累计544秒。
极热T=20：10水未变平原；20水56秒，累计302秒。
加入3株生长期植物：普通雪地10水仍21秒跨界，但累计维持缩短到126秒；普通沙地10水不能跨界，20水28秒跨界、累计330秒。由此不能承诺“10水在任何地块都能改造”。

3格等高的54种环境组合，每个剂量分别统计：
2水：0/54在120秒内跨界。
5水：12/54跨界，主要是靠近温度边界的地块。
10水：36/54跨界。
20水：48/54跨界。
20水失败的6组均为饱和沙地，水向左右排走。把中央改成高度0、两邻格高度1的低洼地后，这6组全部成功：初温16需28秒，初温20需56秒。高度确实影响改造成败，无须强行取消流动。

六、尚未解决的体验与接入事项
1. 植物数在约15～30分钟趋缓，但较满。按每5秒前进一格、无驻足的探测路径，18个投放点平均5.85个到达时已经满容量；驻足更久可能更挤。本轮遵守30秒繁殖和合计5容量，未擅自改变这两项。正式UI必须显示剩余可播数量并阻止扣除放不下的种子；满植物地块仍允许适量投水。若要保证每个点都可播种，需要另定腾位或播种规则。
2. 初始6个水源格在15分钟时都已不再是水洼，原有满水外流、蒸发和再分配逻辑不保证永久水塘。若要求长驻足仍能反复从水洼取水，应另做降雨频率/水源持续性与库存路径测试，不能宣称已解决。
3. 多日离线、存档一致性、雨中玩家取水、实际投放节奏和美术变化尚未在Unity中验收。这里只证明候选数值在所列核心模拟条件下的表现。
4. 正式代码至少需要：每植物生长耗水字段；初始/通用种子品种池与生存地貌分离；基准温度和基准蓄水持久字段；水温公式及类别更新；干土蒸发衰减；阶段回退和成熟双侧传播；驻足时生态继续。调整.asset数字本身不能补齐这些行为。
5. 前景、地表、背景必须按更新后的当前类别刷新，不能始终读取站点初始主题；生态数值跨界不等于现有画面已经会变化。

复现
运行本目录 run.ps1（PowerShell / C# Add-Type），默认输出各类JSON。也可调用 -Sections @('Thermal','Scenarios') 只跑指定部分。Balance.cs 为候选数值和场景，TileState.cs等为源代码快照，TileState_candidate.cs 为自动生成的实验副本。所有源副本均未附带或替换正式美术资产。
